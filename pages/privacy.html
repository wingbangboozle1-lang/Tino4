Privacy & limits

Privacy is a design constraint, not a rounding promise.

Privacy comes first

This public site intentionally contains no property locality, address, parcel identifier, household amount, tax history, rent roll, policy detail, or household-specific recommendation. Use placeholders here and store private records outside the repository.

Why rounding to a round number is not anonymization
Control that was requestedWhy it does not achieve privacy on its ownWhat actually worksEvidenceOfficial source / scope
Round every property figure to the nearest $10Rounding narrows a unique value to a small set; it does not remove the link. County assessment rolls are public and searchable, so an assessed value rounded to the nearest $10 still narrows a county's parcels to a handful, and the roll then supplies the address. Rounding protects against casual reading, not against lookup.Do not publish any assessor's or assessor-derived value at all. Publish the formula and the rate, and keep the amount in the private workpaper.GuidanceCalifornia BOE — Property tax roll and public records · California Revenue and Taxation Code §51
Combine a rounded value with a postal codeThe combination is the problem, not either field. A postal code plus a rounded assessed value plus a unit count plus an inherited-versus-owned status plus a monthly rent is a fingerprint: it can single out one household even when each field has been coarsened.Publish no combination that includes more than one household-specific attribute. Two attributes are usually enough to re-identify; five are far more than enough.GuidanceCalifornia BOE — Property tax roll and public records
Remove names and addresses but keep amountsThe amounts themselves are the identifiers here, because they are recorded against an address in a public roll. Removing the name from a row that still contains a searchable amount is not anonymization; the amount leads back to the name.Treat the amount as the identifier. If it must not appear, the amount is what has to go, not the label.GuidanceCalifornia BOE — Property tax roll and public records · IRS — Gifts and inheritances FAQ
Publish figures because the repository is privateA public GitHub Pages site and a private repository are different systems. If the site is built from repository content, everything published is public regardless of repository visibility, and search engines cache it.Keep the public site free of household amounts entirely, and keep the household model in an offline file that is never committed.GuidanceGitHub Docs — Removing sensitive data from a repository
The one privacy action that matters most

Everything on this page about page content, crisp headers, noindex tags and browser-memory-only calculators is secondary to a single fact: the repository is public and its history still contains the material. A meta tag cannot un-index a Git object. The effective sequence is, in order: decide the repository's visibility, preserve a private encrypted archive, then have the administrator rewrite history and coordinate with GitHub Support about pull-request views and caches. None of that is a website change, and none of it can be done safely from a build script.
